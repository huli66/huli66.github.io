## 1. 安装

```bash

yarn add react-grid-layout

# 或

npm install react-grid-layout

```

**CSS 样式**（必须引入，否则拖拽/调整大小样式会缺失）：

```js

import "react-grid-layout/css/styles.css";

import "react-resizable/css/styles.css";

```

> ⚠️ **不引入 CSS 的后果**：调整大小的把手不可见，拖拽占位符样式丢失，整体视觉效果损坏。

## 2. 核心概念

### 布局项（LayoutItem）

网格中每个元素的位置和大小由一个 `LayoutItem` 对象描述，**所有坐标/尺寸均为网格单位（grid units），不是像素**。

```typescript

interface LayoutItem {

i: string; // 必填：唯一标识符，必须与子元素的 key 一致

x: number; // X 位置（列号，从 0 开始）

y: number; // Y 位置（行号，从 0 开始）

w: number; // 宽度（占几列）

h: number; // 高度（占几行）

minW?: number; // 最小宽度（列数）

maxW?: number; // 最大宽度（列数）

minH?: number; // 最小高度（行数）

maxH?: number; // 最大高度（行数）

static?: boolean; // true = 不可拖拽/调整，其他元素会绕开它

isDraggable?: boolean; // 覆盖网格级别的拖拽设置

isResizable?: boolean; // 覆盖网格级别的调整大小设置

resizeHandles?: ResizeHandleAxis[]; // 覆盖网格级别的调整把手

isBounded?: boolean; // 覆盖网格级别的边界限制

constraints?: LayoutConstraint[]; // 该元素的专属约束

}

type Layout = readonly LayoutItem[];

```

### key 与 i 的对应关系

每个子元素的 React `key` **必须** 与对应 `LayoutItem` 的 `i` 字段完全一致。这是 GridLayout 识别布局项与子元素对应关系的唯一依据。

```jsx

const layout = [{ i: "widget-1", x: 0, y: 0, w: 4, h: 2 }];

<GridLayout layout={layout} width={width}>

<div key="widget-1">内容</div> {/* key 必须 = layout[x].i */}

</GridLayout>

```

## 3. 组件

### 3.1 GridLayout

**主网格布局组件**，基于 Hooks 的函数式组件。

```tsx

import { GridLayout, useContainerWidth } from "react-grid-layout";

function MyGrid() {

const { width, containerRef, mounted } = useContainerWidth();

const layout = [

{ i: "a", x: 0, y: 0, w: 4, h: 2 },

{ i: "b", x: 4, y: 0, w: 4, h: 2 },

];

return (

<div ref={containerRef}>

{mounted && (

<GridLayout

width={width}

layout={layout}

gridConfig={{ cols: 12, rowHeight: 80 }}

onLayoutChange={(newLayout) => console.log(newLayout)}

>

<div key="a">A</div>

<div key="b">B</div>

</GridLayout>

)}

</div>

);

}

```

#### GridLayout Props 完整参考

::: v-pre
| Prop | 类型 | 默认值 | 是否必填 | 说明 |
|------|------|--------|----------|------|
| `children` | `React.ReactNode` | — | ✅ 必填 | 网格子元素，每个必须有唯一 `key` |
| `width` | `number` | — | ✅ 必填 | 容器宽度（像素），通常由 `useContainerWidth` 提供 |
| `layout` | `Layout` | `[]` | 推荐 | 布局定义数组 |
| `gridConfig` | `Partial<GridConfig>` | 见下方 | 否 | 网格尺寸配置 |
| `dragConfig` | `Partial<DragConfig>` | 见下方 | 否 | 拖拽行为配置 |
| `resizeConfig` | `Partial<ResizeConfig>` | 见下方 | 否 | 调整大小配置 |
| `dropConfig` | `Partial<DropConfig>` | 见下方 | 否 | 外部拖入配置 |
| `compactor` | `Compactor` | `verticalCompactor` | 否 | 布局压缩策略 |
| `positionStrategy` | `PositionStrategy` | `transformStrategy` | 否 | CSS 定位策略 |
| `constraints` | `LayoutConstraint[]` | `[gridBounds, minMaxSize]` | 否 | 位置/大小约束 |
| `autoSize` | `boolean` | `true` | 否 | 是否自动调整容器高度 |
| `className` | `string` | `""` | 否 | 容器额外类名 |
| `style` | `CSSProperties` | `{}` | 否 | 容器额外样式 |
| `innerRef` | `React.Ref<HTMLDivElement>` | — | 否 | 容器 DOM ref |
| `droppingItem` | `LayoutItem` | — | 否 | 外部拖入时的占位项定义 |
| `onLayoutChange` | `(layout: Layout) => void` | — | 否 | 布局变化回调 |
| `onDragStart` | `EventCallback` | — | 否 | 拖拽开始回调 |
| `onDrag` | `EventCallback` | — | 否 | 拖拽中回调 |
| `onDragStop` | `EventCallback` | — | 否 | 拖拽结束回调 |
| `onResizeStart` | `EventCallback` | — | 否 | 调整大小开始回调 |
| `onResize` | `EventCallback` | — | 否 | 调整大小中回调 |
| `onResizeStop` | `EventCallback` | — | 否 | 调整大小结束回调 |
| `onDrop` | `(layout, item, e) => void` | — | 否 | 外部元素落下回调 |
| `onDropDragOver` | `(e) => {w?,h?,dragOffsetX?,dragOffsetY?} \| false \| void` | — | 否 | 外部元素拖过网格回调 |
:::

**⚠️ 不传 `width` 的后果**：GridLayout 无法计算列宽和元素位置，布局会完全错乱或不显示。务必使用 `useContainerWidth` hook 提供准确宽度。

**⚠️ 不传 `layout` 的后果**：所有子元素会堆叠在 `x:0, y:0`，无任何布局信息。

#### EventCallback 签名

```typescript

type EventCallback = (

layout: Layout, // 当前完整布局

oldItem: LayoutItem | null, // 变化前的元素状态

newItem: LayoutItem | null, // 变化后的元素状态

placeholder: LayoutItem | null, // 拖拽/调整时的占位元素

event: Event, // 原始 DOM 事件

element: HTMLElement | null // 被操作的 DOM 元素

) => void;

```

### 3.2 ResponsiveGridLayout

响应式网格布局，根据容器宽度自动切换断点和列数。

```tsx

import { ResponsiveGridLayout, useContainerWidth } from "react-grid-layout";

function MyResponsiveGrid() {

const { width, containerRef, mounted } = useContainerWidth();

const layouts = {

lg: [{ i: "a", x: 0, y: 0, w: 6, h: 2 }],

md: [{ i: "a", x: 0, y: 0, w: 5, h: 2 }],

sm: [{ i: "a", x: 0, y: 0, w: 6, h: 2 }],

};

return (

<div ref={containerRef}>

{mounted && (

<ResponsiveGridLayout

width={width}

layouts={layouts}

breakpoints={{ lg: 1200, md: 996, sm: 768, xs: 480, xxs: 0 }}

cols={{ lg: 12, md: 10, sm: 6, xs: 4, xxs: 2 }}

rowHeight={100}

onLayoutChange={(layout, allLayouts) => console.log(layout, allLayouts)}

onBreakpointChange={(bp, cols) => console.log(bp, cols)}

>

<div key="a">响应式内容</div>

</ResponsiveGridLayout>

)}

</div>

);

}

```

#### ResponsiveGridLayout Props 完整参考

除继承所有 `GridLayout` 的 props（`gridConfig`、`layout`、`onLayoutChange` 除外）之外，新增以下 props：

::: v-pre
| Prop | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `breakpoints` | `Record<B, number>` | `{ lg:1200, md:996, sm:768, xs:480, xxs:0 }` | 断点名称 → 最小宽度映射 |
| `cols` | `Record<B, number>` | `{ lg:12, md:10, sm:6, xs:4, xxs:2 }` | 各断点的列数 |
| `layouts` | `Partial<Record<B, Layout>>` | `{}` | 各断点的布局定义 |
| `rowHeight` | `number` | `150` | 单行像素高度 |
| `maxRows` | `number` | `Infinity` | 最大行数 |
| `margin` | `[number, number] \| Record<B, [number, number]>` | `[10, 10]` | 元素间距（可按断点配置） |
| `containerPadding` | `[number, number] \| Record<B, [number,number]\|null> \| null` | `null` | 容器内边距（可按断点配置） |
| `compactor` | `Compactor` | `verticalCompactor` | 压缩策略 |
| `breakpoint` | `B` | 自动检测 | 手动指定当前断点（覆盖自动检测） |
| `onBreakpointChange` | `(bp: B, cols: number) => void` | — | 断点变化回调 |
| `onLayoutChange` | `(layout: Layout, layouts: ResponsiveLayouts<B>) => void` | — | 布局变化回调（参数比 GridLayout 多一个 layouts） |
| `onWidthChange` | `(width, margin, cols, containerPadding) => void` | — | 宽度变化回调 |
:::

**⚠️ 注意**：`ResponsiveGridLayout` 的 `onLayoutChange` 签名与 `GridLayout` 不同，多了第二个参数 `layouts`（所有断点的完整布局）。混用会导致布局状态丢失。

**布局自动生成规则**：若某个断点没有对应的 `layouts` 定义，会从最近的较大断点的布局自动生成，并在列数缩减时重新压缩。

## 4. Hooks

### 4.1 useContainerWidth

测量并实时追踪容器宽度，替代旧版 `WidthProvider` HOC。内部使用 `ResizeObserver`。

```tsx

import { useContainerWidth } from "react-grid-layout";

const { width, containerRef, mounted, measureWidth } = useContainerWidth({

measureBeforeMount: false, // 是否在挂载前先测量（SSR 场景有用）

initialWidth: 1280, // 测量前的初始宽度

});

```

#### 参数（UseContainerWidthOptions）

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `measureBeforeMount` | `boolean` | `false` | 为 `true` 时，在首次测量完成前 `mounted` 保持 `false`，适合 SSR 或需要精确初始尺寸的场景 |
| `initialWidth` | `number` | `1280` | 测量完成前使用的默认宽度 |

#### 返回值（UseContainerWidthResult）

::: v-pre
| 字段 | 类型 | 说明 |
|------|------|------|
| `width` | `number` | 当前容器宽度（像素） |
| `mounted` | `boolean` | 是否已完成至少一次宽度测量 |
| `containerRef` | `RefObject<HTMLDivElement>` | 绑定到容器元素的 ref |
| `measureWidth` | `() => void` | 手动触发一次测量（容器大小变化但未触发 ResizeObserver 时使用） |
:::

**推荐用法**（配合 `mounted` 避免服务端渲染问题）：

```tsx

const { width, containerRef, mounted } = useContainerWidth();

return (

<div ref={containerRef}>

{mounted && <GridLayout width={width} .../>}

</div>

);

```

**⚠️ 不用 `mounted` 保护直接渲染的问题**：首次渲染时 `width` 为初始值（1280），可能导致布局闪烁（先按 1280px 渲染，再立即按实际宽度重新渲染）。使用 `mounted && ...` 可确保只在测量完成后渲染。

### 4.2 useGridLayout

底层网格状态管理 Hook，将布局状态逻辑从 GridLayout 组件中提取出来，适合需要完全自定义渲染的场景。

```tsx

import { useGridLayout } from "react-grid-layout";

const {

layout,

setLayout,

dragState,

resizeState,

dropState,

onDragStart,

onDrag,

onDragStop,

onResizeStart,

onResize,

onResizeStop,

onDropDragOver,

onDropDragLeave,

onDrop,

containerHeight,

isInteracting,

compactor,

} = useGridLayout({

layout: initialLayout,

cols: 12,

preventCollision: false,

onLayoutChange: (newLayout) => console.log(newLayout),

compactor: verticalCompactor,

});

```

#### 参数（UseGridLayoutOptions）

::: v-pre
| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `layout` | `Layout` | — | ✅ 必填：初始布局 |
| `cols` | `number` | — | ✅ 必填：列数 |
| `preventCollision` | `boolean` | `false` | 是否阻止碰撞（拖拽时不推开其他元素） |
| `onLayoutChange` | `(layout: Layout) => void` | — | 布局变化回调 |
| `compactor` | `Compactor` | `verticalCompactor` | 压缩策略 |
:::

#### 返回值（UseGridLayoutResult）

::: v-pre
| 字段 | 类型 | 说明 |
|------|------|------|
| `layout` | `Layout` | 当前布局状态 |
| `setLayout` | `(layout: Layout) => void` | 直接设置布局（会触发压缩） |
| `dragState` | `DragState` | 拖拽状态（activeDrag, oldDragItem, oldLayout） |
| `resizeState` | `ResizeState` | 调整大小状态（resizing, oldResizeItem, oldLayout） |
| `dropState` | `DropState` | 外部拖入状态 |
| `onDragStart` | `(itemId, x, y) => LayoutItem \| null` | 开始拖拽 |
| `onDrag` | `(itemId, x, y) => void` | 拖拽中更新 |
| `onDragStop` | `(itemId, x, y) => void` | 结束拖拽 |
| `onResizeStart` | `(itemId) => LayoutItem \| null` | 开始调整大小 |
| `onResize` | `(itemId, w, h, x?, y?) => void` | 调整大小中更新 |
| `onResizeStop` | `(itemId, w, h) => void` | 结束调整大小 |
| `onDropDragOver` | `(droppingItem, position) => void` | 外部拖入悬停 |
| `onDropDragLeave` | `() => void` | 外部拖入离开 |
| `onDrop` | `(droppingItem) => void` | 外部拖入落下 |
| `containerHeight` | `number` | 当前容器高度（行数） |
| `isInteracting` | `boolean` | 是否有任何拖拽/调整中 |
| `compactor` | `Compactor` | 当前使用的压缩器 |
:::

> 通常直接使用 `GridLayout` 组件即可，`useGridLayout` 适合需要完全自定义 UI 的高级场景。

### 4.3 useResponsiveLayout

响应式断点布局状态管理 Hook，提取自 `ResponsiveGridLayout` 的状态逻辑。

```tsx

import { useContainerWidth, useResponsiveLayout, GridLayout } from "react-grid-layout";

function MyCustomResponsiveGrid() {

const { width, containerRef, mounted } = useContainerWidth();

const { layout, breakpoint, cols, setLayoutForBreakpoint } = useResponsiveLayout({

width,

layouts: { lg: [...], md: [...] },

breakpoints: { lg: 1200, md: 996, sm: 768, xs: 480, xxs: 0 },

cols: { lg: 12, md: 10, sm: 6, xs: 4, xxs: 2 },

compactor: verticalCompactor,

onBreakpointChange: (bp, cols) => console.log("断点变化:", bp, cols),

onLayoutChange: (layout, layouts) => console.log(layout),

});

return (

<div ref={containerRef}>

{mounted && (

<GridLayout

width={width}

layout={layout}

gridConfig={{ cols, rowHeight: 100 }}

>

{children}

</GridLayout>

)}

</div>

);

}

```

#### 参数（UseResponsiveLayoutOptions）

::: v-pre
| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `width` | `number` | — | ✅ 必填：当前容器宽度 |
| `breakpoints` | `Record<B, number>` | `{ lg:1200, md:996, sm:768, xs:480, xxs:0 }` | 断点定义 |
| `cols` | `Record<B, number>` | `{ lg:12, md:10, sm:6, xs:4, xxs:2 }` | 各断点列数 |
| `layouts` | `ResponsiveLayouts<B>` | `{}` | 各断点布局 |
| `compactor` | `Compactor` | `verticalCompactor` | 压缩策略 |
| `onBreakpointChange` | `(bp, cols) => void` | — | 断点变化回调 |
| `onLayoutChange` | `(layout, layouts) => void` | — | 布局变化回调 |
| `onWidthChange` | `(width, margin, cols, padding) => void` | — | 宽度变化回调 |
:::

#### 返回值（UseResponsiveLayoutResult）

::: v-pre
| 字段 | 类型 | 说明 |
|------|------|------|
| `layout` | `Layout` | 当前断点的布局 |
| `layouts` | `ResponsiveLayouts<B>` | 所有断点的完整布局 |
| `breakpoint` | `B` | 当前激活的断点名称 |
| `cols` | `number` | 当前断点的列数 |
| `setLayoutForBreakpoint` | `(bp, layout) => void` | 更新某个断点的布局 |
| `setLayouts` | `(layouts) => void` | 更新所有断点的布局 |
| `sortedBreakpoints` | `B[]` | 按宽度从小到大排列的断点名称数组 |
:::

## 5. 配置接口

v2 将原本扁平的 props 拆分为四个可组合的配置对象。

### 5.1 GridConfig

网格尺寸配置，传给 `gridConfig` prop。

```typescript

interface GridConfig {

cols: number; // 列数，默认 12

rowHeight: number; // 单行像素高度，默认 150

margin: readonly [number, number]; // 元素间距 [水平, 垂直]，默认 [10, 10]

containerPadding: readonly [number, number] | null; // 容器内边距，默认 null（使用 margin 值）

maxRows: number; // 最大行数，默认 Infinity

}

```

| 属性 | 默认值 | 不配置的影响 |
|------|--------|-------------|
| `cols` | `12` | 使用 12 列网格 |
| `rowHeight` | `150` | 每行高 150px，可能过高/过低 |
| `margin` | `[10, 10]` | 元素之间有 10px 水平和垂直间距 |
| `containerPadding` | `null`（使用 margin） | 容器四周等于 margin 值 |
| `maxRows` | `Infinity` | 无限行数，元素可无限向下堆积 |

**示例**：

```tsx

<GridLayout

gridConfig={{

cols: 12,

rowHeight: 60,

margin: [8, 8],

containerPadding: [16, 16],

maxRows: 20,

}}

/>

```

### 5.2 DragConfig

拖拽行为配置，传给 `dragConfig` prop。

```typescript

interface DragConfig {

enabled: boolean; // 是否可拖拽，默认 true

bounded: boolean; // 是否限制在容器内，默认 false

handle?: string; // 拖拽把手的 CSS 选择器（如 ".drag-handle"）

cancel?: string; // 不触发拖拽的区域的 CSS 选择器

threshold: number; // 触发拖拽的最小移动像素，默认 3

}

```

| 属性 | 默认值 | 不配置的影响 |
|------|--------|-------------|
| `enabled` | `true` | 所有元素可拖拽 |
| `bounded` | `false` | 元素可被拖出容器边界 |
| `handle` | — | 整个元素都是拖拽区域 |
| `cancel` | — | 无任何禁止区域 |
| `threshold` | `3` | 移动 3px 后才开始拖拽，避免点击误触发 |

**常用场景**：

```tsx

// 只允许通过特定把手拖拽

<GridLayout dragConfig={{ handle: ".drag-handle" }} />

// 禁止拖拽

<GridLayout dragConfig={{ enabled: false }} />

// 限制在容器内

<GridLayout dragConfig={{ bounded: true }} />

// 防止表单元素触发拖拽

<GridLayout dragConfig={{ cancel: "input, button, select" }} />

```

### 5.3 ResizeConfig

调整大小配置，传给 `resizeConfig` prop。

```typescript

interface ResizeConfig {

enabled: boolean; // 是否可调整大小，默认 true

handles: readonly ResizeHandleAxis[]; // 显示哪些方向的调整把手，默认 ['se']

handleComponent?: React.ReactNode | ((axis: ResizeHandleAxis, ref: React.Ref<HTMLElement>) => React.ReactNode); // 自定义调整把手组件

}

type ResizeHandleAxis = 's' | 'w' | 'e' | 'n' | 'sw' | 'nw' | 'se' | 'ne';

// 南 西 东 北 西南 西北 东南 东北

```

| 属性 | 默认值 | 不配置的影响 |
|------|--------|-------------|
| `enabled` | `true` | 所有元素可调整大小 |
| `handles` | `['se']` | 只有右下角可拖拽调整 |
| `handleComponent` | — | 使用默认的调整把手样式 |

**示例**：

```tsx

// 启用全部 8 个方向的调整把手

<GridLayout resizeConfig={{ handles: ['s', 'w', 'e', 'n', 'sw', 'nw', 'se', 'ne'] }} />

// 禁止调整大小

<GridLayout resizeConfig={{ enabled: false }} />

// 自定义把手组件

<GridLayout resizeConfig={{

handles: ['se'],

handleComponent: (axis, ref) => (

<div ref={ref} className="my-resize-handle" data-axis={axis}>⊞</div>

)

}} />

```

### 5.4 DropConfig

外部元素拖入配置，传给 `dropConfig` prop。默认关闭。

```typescript

interface DropConfig {

enabled: boolean; // 是否接受外部拖入，默认 false

defaultItem: { w: number; h: number }; // 拖入元素的默认大小，默认 {w:1, h:1}

onDragOver?: (e: DragEvent) => { w?: number; h?: number; dragOffsetX?: number; dragOffsetY?: number } | false | void; // 返回 false = 拒绝此次拖入

}

```

**示例**：

```tsx

<GridLayout

if (type === "big-widget") return { w: 4, h: 3 };

if (type === "forbidden") return false; // 拒绝

return { w: 2, h: 2 };

}

}}

onDrop={(layout, item, e) => {

console.log("新元素落下在:", item);

}}

/>

```

## 6. 压缩器

压缩器（Compactor）决定元素在拖拽/调整大小后如何自动填充空隙。

### 内置压缩器

| 压缩器 | 导入方式 | 行为 |
|--------|---------|------|
| `verticalCompactor` | `import { verticalCompactor } from "react-grid-layout"` | 元素向上浮动填充空隙（**默认**） |
| `horizontalCompactor` | `import { horizontalCompactor } from "react-grid-layout"` | 元素向左浮动填充空隙 |
| `noCompactor` | `import { noCompactor } from "react-grid-layout"` | 自由定位，不自动填充空隙 |
| `verticalOverlapCompactor` | `import { verticalOverlapCompactor } from "react-grid-layout/core"` | 向上浮动，但**允许重叠** |
| `horizontalOverlapCompactor` | `import { horizontalOverlapCompactor } from "react-grid-layout/core"` | 向左浮动，但**允许重叠** |
| `noOverlapCompactor` | `import { noOverlapCompactor } from "react-grid-layout/core"` | 自由定位，**允许重叠** |

### Compactor 接口

```typescript

interface Compactor {

readonly type: "horizontal" | "vertical" | "wrap" | null;

readonly allowOverlap: boolean;

readonly preventCollision?: boolean; // true = 拖拽时阻止覆盖（不推开其他元素）

compact(layout: Layout, cols: number): Layout;

}

```

### 不同压缩器的效果对比

| | 拖拽后 | 删除元素后 | 适用场景 |
|--|--------|-----------|----------|
| `verticalCompactor` | 其他元素向上填充 | 空隙被填充 | 仪表盘、卡片布局 |
| `horizontalCompactor` | 其他元素向左填充 | 空隙被填充 | 水平排布的工具栏 |
| `noCompactor` | 元素保持原位 | 产生空隙 | 自由布局、Canvas 类场景 |
| `noOverlapCompactor` | 元素保持原位，可重叠 | 产生空隙 | 图层叠加场景 |

### 通过 `getCompactor` 动态创建

```typescript

import { getCompactor } from "react-grid-layout";

// 参数：(compactType, allowOverlap, preventCollision)

const myCompactor = getCompactor("vertical", false, true);

// preventCollision=true：拖拽时撞到其他元素会弹回，而不是推开对方

```

### 自定义压缩器

```typescript

const myCompactor: Compactor = {

type: "vertical",

allowOverlap: false,

compact(layout, cols) {

// 自定义压缩逻辑

return myCustomSort(layout);

}

};

<GridLayout compactor={myCompactor} />

```

## 7. 定位策略

定位策略（PositionStrategy）控制网格元素的 CSS 定位方式。

### 内置策略

| 策略 | 导入方式 | 说明 |
|------|---------|------|
| `transformStrategy` | `import { transformStrategy } from "react-grid-layout"` | 使用 `transform: translate()` 定位（**默认**，性能最佳） |
| `absoluteStrategy` | `import { absoluteStrategy } from "react-grid-layout"` | 使用 `top/left` 定位（适合打印、PDF 导出等场景） |
| `createScaledStrategy(scale)` | `import { createScaledStrategy } from "react-grid-layout"` | 缩放容器内的 transform 定位 |

### 使用缩放策略

当网格容器被 CSS `transform: scale()` 缩放时，拖拽坐标会产生偏差，需使用 `createScaledStrategy`：

```tsx

import { createScaledStrategy } from "react-grid-layout";

// 父容器被缩放为 0.5 倍

<div style={{ transform: 'scale(0.5)', transformOrigin: 'top left' }}>

<GridLayout

positionStrategy={createScaledStrategy(0.5)}

width={width / 0.5} // 注意：width 也要相应调整

/>

</div>

```

**⚠️ 不使用 `createScaledStrategy` 而父容器有 scale 的后果**：拖拽时元素会出现严重偏移，鼠标位置与元素位置不匹配。

## 8. 布局约束

约束（Constraints）在拖拽和调整大小时限制元素的位置和尺寸。约束是可组合的数组，**按数组顺序依次应用**。

### 内置约束

| 约束 | 导入方式 | 作用 |
|------|---------|------|
| `gridBounds` | `import { gridBounds } from "react-grid-layout"` | 保持元素在网格范围内（x: 0~cols，y: 0~maxRows）|
| `minMaxSize` | `import { minMaxSize } from "react-grid-layout"` | 执行元素的 minW/maxW/minH/maxH 限制 |
| `containerBounds` | `import { containerBounds } from "react-grid-layout"` | 限制在可见容器高度内（与实际像素高度相关） |
| `boundedX` | `import { boundedX } from "react-grid-layout"` | 只限制水平方向，Y 轴自由 |
| `boundedY` | `import { boundedY } from "react-grid-layout"` | 只限制垂直方向，X 轴自由 |
| `defaultConstraints` | `import { defaultConstraints } from "react-grid-layout"` | 默认约束组合：`[gridBounds, minMaxSize]` |

### 约束工厂函数

| 函数 | 参数 | 说明 |
|------|------|------|
| `aspectRatio(ratio)` | `ratio: number`（宽/高，如 16/9） | 调整大小时保持像素宽高比 |
| `snapToGrid(stepX, stepY?)` | `stepX, stepY: number` | 位置对齐到指定网格步长 |
| `minSize(minW, minH)` | `minW, minH: number` | 为所有元素设置全局最小尺寸 |
| `maxSize(maxW, maxH)` | `maxW, maxH: number` | 为所有元素设置全局最大尺寸 |

```tsx

import {

gridBounds, minMaxSize, aspectRatio, snapToGrid

} from "react-grid-layout";

// 网格级约束（应用于所有元素）

<GridLayout constraints={[gridBounds, minMaxSize, snapToGrid(2)]} />

// 结合宽高比约束

<GridLayout constraints={[gridBounds, minMaxSize, aspectRatio(16/9)]} />

```

### 元素级约束（per-item）

通过 `LayoutItem.constraints` 为单个元素设置专属约束：

```typescript

const layout = [

{

i: "video",

x: 0, y: 0, w: 4, h: 6,

constraints: [aspectRatio(16 / 9)] // 只有这个元素保持 16:9

},

{

i: "square",

x: 4, y: 0, w: 3, h: 3,

constraints: [aspectRatio(1)] // 正方形

}

];

```

**执行顺序**：网格级约束先执行，再执行元素级约束。

### 自定义约束

```typescript

import type { LayoutConstraint } from "react-grid-layout";

const myConstraint: LayoutConstraint = {

name: "myConstraint", // 调试用标识

// 限制位置（拖拽时调用）

constrainPosition(item, x, y, { cols }) {

// 只允许在偶数列

return { x: Math.round(x / 2) * 2, y };

},

// 限制尺寸（调整大小时调用）

constrainSize(item, w, h, handle, context) {

// 宽度只允许偶数

return { w: Math.round(w / 2) * 2, h };

}

};

```

**⚠️ 重要**：约束仅在拖拽/调整大小时生效，不影响初始布局的设置。

**⚠️ `gridBounds` 与 `containerBounds` 的区别**：

- `gridBounds` 使用 `maxRows`（可能是 `Infinity`）

- `containerBounds` 根据容器实际像素高度计算可见行数，更适合固定高度容器

## 11. 使用要点与常见问题

### ✅ 要点一：children 必须记忆化（memoize）

GridLayout 通过引用比较子元素来决定是否重新渲染。如果 `children` 在每次父组件渲染时都重新创建，会导致整个网格频繁重渲染。

```tsx

// ❌ 错误：children 每次渲染都是新数组

function BadGrid() {

const [count, setCount] = useState(0);

return (

<GridLayout width={width} layout={layout}>

{items.map(item => <div key={item.id}>{item.name}</div>)}

</GridLayout>

);

}

// ✅ 正确：用 useMemo 缓存 children

function GoodGrid() {

const [count, setCount] = useState(0);

const children = useMemo(

() => items.map(item => <div key={item.id}>{item.name}</div>),

[items] // 只有 items 变化时才重新创建

);

return <GridLayout width={width} layout={layout}>{children}</GridLayout>;

}

```

### ✅ 要点二：受控模式（Controlled Mode）

GridLayout 支持受控模式，需要在 `onLayoutChange` 中更新 `layout`：

```tsx

const [layout, setLayout] = useState(initialLayout);

<GridLayout

layout={layout}

onLayoutChange={(newLayout) => setLayout(newLayout)}

/>

```

**⚠️ 注意**：`onLayoutChange` 返回的是不可变数组（`readonly LayoutItem[]`），不能直接 `.push()` 修改，需要展开或替换。

### ✅ 要点三：自定义组件作为网格子项

自定义组件必须转发 ref 和特定 props，否则拖拽/调整大小无法工作：

```tsx

import { forwardRef } from "react";

const CustomWidget = forwardRef<HTMLDivElement, {

style?: React.CSSProperties;

className?: string;

onMouseDown?: React.MouseEventHandler;

onMouseUp?: React.MouseEventHandler;

onTouchEnd?: React.TouchEventHandler;

children?: React.ReactNode;

}>(({ style, className, onMouseDown, onMouseUp, onTouchEnd, children, ...rest }, ref) => (

<div

ref={ref}

style={style}

className={className}

onMouseDown={onMouseDown}

onMouseUp={onMouseUp}

onTouchEnd={onTouchEnd}

>

{/* children 必须渲染，包含调整大小的把手 */}

{children}

{/* 自定义内容 */}

<div className="widget-content">...</div>

</div>

));

```

**⚠️ 不转发 `children` 的后果**：调整大小的把手不会显示，无法调整元素大小。

### ✅ 要点四：SSR（服务端渲染）

在 Next.js 等 SSR 环境中，`ResizeObserver` 不存在，需要正确处理：

```tsx

// 方案一：使用 measureBeforeMount（推荐）

const { width, containerRef, mounted } = useContainerWidth({

measureBeforeMount: true, // mounted 在首次测量后才变 true

initialWidth: 1200, // SSR 时的占位宽度

});

// mounted && 保证客户端测量完成后才渲染

return (

<div ref={containerRef}>

{mounted && <GridLayout width={width} .../>}

</div>

);

// 方案二：动态导入（Next.js）

const GridLayout = dynamic(() => import("./MyGrid"), { ssr: false });

```

### ✅ 要点五：性能优化

```tsx

// 1. 稳定化 gridConfig、dragConfig 等对象引用

const gridConfig = useMemo(() => ({ cols: 12, rowHeight: 60 }), []);

const dragConfig = useMemo(() => ({ handle: ".drag-handle" }), []);

// 2. 稳定化回调函数

const handleLayoutChange = useCallback((newLayout) => {

setLayout(newLayout);

}, []);

// 3. 稳定化 compactor（使用模块级常量，不要每次渲染都创建）

import { verticalCompactor } from "react-grid-layout"; // 直接用导入的常量

<GridLayout

gridConfig={gridConfig}

dragConfig={dragConfig}

compactor={verticalCompactor} // 常量引用，不会触发重新渲染

onLayoutChange={handleLayoutChange}

>

{children}

</GridLayout>

```

### ❌ 常见问题

::: v-pre
| 问题现象 | 原因 | 解决方案 |
|---------|------|---------|
| 元素全部堆在左上角 | 没有传 `layout` 或 `key` 与 `i` 不匹配 | 确保每个子元素 `key === layout[n].i` |
| 拖拽时抖动或偏移严重 | 父容器有 CSS scale 但未用 `createScaledStrategy` | 使用 `positionStrategy={createScaledStrategy(scale)}` |
| 调整大小把手不显示 | 没有引入 CSS 文件 | 引入 `react-resizable/css/styles.css` |
| 布局初始化闪烁 | 未使用 `mounted` 保护渲染 | 用 `{mounted && <GridLayout.../>}` 包裹 |
| 受控模式下布局不更新 | `onLayoutChange` 未调用 `setLayout` | 确保在回调中更新 `layout` 状态 |
| 每次父组件渲染都触发网格重渲染 | `children` 未记忆化 | 用 `useMemo` 包裹 `children` |
| ResponsiveGridLayout 切换断点时布局错乱 | 没有为所有断点提供布局 | 至少提供最大断点的布局，其他会自动生成 |
| 元素不能拖出容器 | `dragConfig.bounded: true` 或使用了 `containerBounds` 约束 | 移除这些设置 |
| 静态元素（`static: true`）无法交互 | 正常行为 | 若需要交互，在 `LayoutItem` 中去掉 `static: true` |
| `maxRows` 设置后元素仍然超出 | 只限制拖拽目标位置，不限制调整大小 | 同时在约束中加入 `gridBounds` |
:::


## 12. 默认特性速查表

> 本章汇总库内所有隐式默认行为，帮助你预判"不设置某个属性时会发生什么"。

---

### 12.1 配置默认值

| 配置对象 | 属性 | 默认值 | 说明 |
|---|---|---|---|
| `GridConfig` | `cols` | `12` | 12 列网格 |
| `GridConfig` | `rowHeight` | `150` | 每行 150px |
| `GridConfig` | `margin` | `[10, 10]` | 水平/垂直间距均为 10px |
| `GridConfig` | `containerPadding` | `null` | 为 `null` 时自动使用 `margin` 的值作为内边距 |
| `GridConfig` | `maxRows` | `Infinity` | 行数不受限制 |
| `DragConfig` | `enabled` | `true` | 所有元素默认可拖拽 |
| `DragConfig` | `bounded` | `false` | 默认不限制拖拽在容器内 |
| `DragConfig` | `threshold` | `3` | 移动超过 3px 才触发拖拽，区分点击与拖拽 |
| `ResizeConfig` | `enabled` | `true` | 所有元素默认可调整大小 |
| `ResizeConfig` | `handles` | `["se"]` | 仅右下角有调整把手 |
| `DropConfig` | `enabled` | `false` | 默认关闭外部拖入 |
| `DropConfig` | `defaultItem` | `{ w: 1, h: 1 }` | 外部拖入元素默认占 1×1 格 |

---

### 12.2 GridLayout 组件默认行为

| 属性/行为 | 默认值 | 说明 |
|---|---|---|
| `autoSize` | `true` | 容器高度自动跟随内容调整，无需手动设置高度 |
| `compactor` | `verticalCompactor` | 自动向上（垂直）压缩，消除空白行 |
| `constraints` | `[gridBounds, minMaxSize]` | 自动限制元素不超出网格边界，且遵守 minW/maxW/minH/maxH |
| `positionStrategy` | `transformStrategy` | 使用 CSS `transform: translate()` 定位，GPU 加速，性能最优 |
| `layout` | `[]` | 初始布局为空，通过子元素 key 和 `data-grid` prop 自动生成 |

**初始化流程（隐式触发，每次挂载或 layout/children 变化时）**：

1. 遍历所有子元素，根据 `key` 匹配 `layout` 数组

2. **未匹配的子元素**：若有 `data-grid` prop → 从中读取位置；否则 → `{ x:0, y:bottom, w:1, h:1 }`

3. 执行 `correctBounds`（修正超出列数范围的元素）

4. 执行 `compactor.compact()`（按当前压缩器压缩布局）

5. 若结果与传入 `layout` 不同，**立即触发一次 `onLayoutChange`**

---

### 12.3 LayoutItem 属性的默认与继承规则

| LayoutItem 属性 | 默认来源 | 说明 |
|---|---|---|
| `isDraggable` | 继承 `dragConfig.enabled`（即 `true`）| 单独设置可覆盖全局配置 |
| `isResizable` | 继承 `resizeConfig.enabled`（即 `true`）| 单独设置可覆盖全局配置 |
| `resizeHandles` | 继承 `resizeConfig.handles`（即 `["se"]`）| 单独设置可覆盖全局配置 |
| `isBounded` | 继承 `dragConfig.bounded`（即 `false`）| 单独设置可覆盖全局配置 |
| `minW` | `1` | 最小宽度为 1 列 |
| `maxW` | `Infinity` | 宽度无上限 |
| `minH` | `1` | 最小高度为 1 行 |
| `maxH` | `Infinity` | 高度无上限 |
| `static` | `false`（未设置即非静态）| `true` 时同时禁用拖拽和缩放 |

> **`static: true` 的特殊行为**：静态元素自身不可移动、不可缩放，且压缩时其他元素会**绕行**而不是穿透它，静态元素是整个网格的"锚点"。

### 12.4 CSS 类名（运行时自动附加）

网格库会在运行时自动给 DOM 元素附加以下类名，可用于 CSS 自定义样式：

| 类名 | 附加到 | 触发条件 |
|---|---|---|
| `.react-grid-layout` | 容器 `div` | 始终存在 |
| `.react-grid-item` | 每个网格元素 | 始终存在 |
| `.react-grid-placeholder` | 占位元素 | 拖拽或调整大小时，显示目标落点 |
| `.placeholder-resizing` | 占位元素 | 正在调整大小时额外附加 |
| `.static` | 网格元素 | `static: true` |
| `.resizing` | 网格元素 | 正在调整大小中 |
| `.react-draggable` | 网格元素 | `isDraggable: true` |
| `.react-draggable-dragging` | 网格元素 | 正在拖拽中 |
| `.dropping` | 网格元素 | 外部拖入的占位元素 |
| `.cssTransforms` | 网格元素 | 使用 CSS transform 定位（`transformStrategy`）时 |
| `.react-resizable-hide` | 网格元素 | `isResizable: false`，同时隐藏调整把手 |

```css

/* 示例：拖拽中的元素半透明 */

.react-grid-item.react-draggable-dragging {

opacity: 0.7;

z-index: 100;

}

/* 示例：占位符蓝色虚线边框 */

.react-grid-placeholder {

background: rgba(59, 130, 246, 0.15) !important;

border: 2px dashed #3b82f6;

}

```

### 12.5 布局同步默认行为

**子元素增加时**（新 key 未在 layout 中）：

- 有 `data-grid` prop → 使用 `data-grid` 的 x/y/w/h

- 无 `data-grid` prop → 自动放置在 `{ x:0, y:bottom(currentLayout), w:1, h:1 }`

**子元素删除时**：对应 layout 项**自动移除**，其余元素按压缩器规则重新排列。

**layout prop 变化时**：

- **拖拽/缩放进行中** → 忽略外部 layout 变化，以防止竞态

- **空闲时** → 正常同步，触发压缩并调用 `onLayoutChange`

**外部拖入（drop）临时元素**：

- 悬浮期间插入 id 为 `__dropping-elem__` 的临时占位

- **不通过 `onLayoutChange` 暴露**，仅在用户确认放下（`onDrop` 触发）后才由业务层决定是否加入 layout

---

### 12.6 定位策略默认行为

`transformStrategy`（默认）使用 CSS `transform: translate(xpx, ypx)` 定位，特点：

- **GPU 加速**，拖拽/动画更流畅

- 元素保持 `position: absolute`，通过 transform 做视觉偏移

- 对大多数场景无需关注，直接使用即可

> ⚠️ 若在**已缩放容器**（如 CSS `transform: scale(0.5)`）内使用，拖拽坐标会产生偏差。

> 解决方案：改用 `createScaledStrategy(scale)` 传递缩放比例，或改用 `absoluteStrategy`。

### 12.7 containerPadding 为 null 的计算规则

```ts

containerPadding: null // 默认值

```

`containerPadding` 为 `null` 时，内部自动将 `margin` 的值作为容器内边距使用：

```

// 等效于：

containerPadding = margin // 如默认的 [10, 10]

```

**列宽计算公式**：

```

colWidth = (containerWidth - margin[0] * (cols - 1) - containerPadding[0] * 2) / cols

```

若希望网格元素与容器边缘的距离和元素间距不同，需显式设置 `containerPadding`：

```ts

gridConfig={{

margin: [10, 10], // 元素间距 10px

containerPadding: [20, 20] // 容器边缘 20px

}}

```

### 12.8 拖拽阈值（threshold）默认行为

`DragConfig.threshold` 默认为 `3`（像素）：

- 鼠标按下后**必须移动超过 3px** 才触发拖拽

- 小于 3px 的轻微移动视为**点击**，不触发 `onDragStart`/`onDrag`/`onDragStop`

- 若需更敏感的响应：<code v-pre>dragConfig={{ threshold: 0 }}</code>

- 若需防误操作（如复杂表单）：<code v-pre>dragConfig={{ threshold: 10 }}</code>

### 12.9 ResponsiveGridLayout 断点默认值

```ts

// 默认断点（宽度阈值，单位：px）

breakpoints = { lg: 1200, md: 996, sm: 768, xs: 480, xxs: 0 }

// 默认列数

cols = { lg: 12, md: 10, sm: 6, xs: 4, xxs: 2 }

```

**断点切换时的 layout 自动生成规则**：

1. 目标断点 layout 已存在 → 直接使用

2. 不存在 → 从**最近的较大断点** layout 克隆，在新列数下重新压缩

3. 所有较大断点都无 layout → 从子元素 `data-grid`/key 生成初始布局

> 这意味着即使只提供 `lg` 的 layout，其他断点也能自动降级，**但降级结果可能不是你期望的布局**。建议为每个断点都提供专门的 layout。

### 12.10 useContainerWidth 默认行为

```ts

const { width, mounted, containerRef } = useContainerWidth({

initialWidth: 1280, // 默认：1280px（SSR 占位值）

measureBeforeMount: false // 默认：false

});

```

| 参数 | 默认值 | 说明 |
|---|---|---|
| `initialWidth` | `1280` | SSR 或首次渲染前使用的占位宽度，避免 0 宽度导致布局错乱 |
| `measureBeforeMount` | `false` | `false` 时 `mounted` 从 `true` 开始，组件立即渲染；`true` 时等待实际测量后再渲染 |

- 内部使用 `ResizeObserver` 监听容器宽度变化

- 宽度更新通过 `requestAnimationFrame` 延迟，**自动规避 "ResizeObserver loop limit exceeded" 报错**

- SSR 场景建议设置 `measureBeforeMount: true` 防止初始宽度闪烁：

```tsx

const { width, mounted, containerRef } = useContainerWidth({ measureBeforeMount: true });

return (

<div ref={containerRef}>

{mounted && <GridLayout width={width} />}

</div>

);

```

### 12.11 默认约束（defaultConstraints）

不传 `constraints` prop 时，`GridLayout` 自动应用 `[gridBounds, minMaxSize]`：

| 约束 | 效果 |
|---|---|
| `gridBounds` | 元素不能拖出网格左右边界（x ≥ 0，x+w ≤ cols），不能超出 maxRows |
| `minMaxSize` | 元素尺寸严格遵守 LayoutItem 的 minW/maxW/minH/maxH |

```ts

// 传空数组 = 完全禁用所有约束（元素可拖出边界、缩到 0）

constraints={[]}

// 追加额外约束时，需显式包含默认约束

import { gridBounds, minMaxSize, aspectRatio } from "react-grid-layout";

constraints={[gridBounds, minMaxSize, aspectRatio(16 / 9)]}

```

### 12.12 调整把手对拖拽的自动排除

调整大小的把手（`.react-resizable-handle`）被**自动从拖拽触发区域中排除**，内部通过 `DraggableCore` 的 `cancel` 参数实现：

```ts

cancel=".react-resizable-handle" // 自动附加，无需配置

```

即：即使整个元素都是可拖拽区域，点击到调整把手时**只触发缩放，不触发拖拽**。这是无需配置的内置行为。

若你自定义了 `dragConfig.cancel`，库会自动将 `.react-resizable-handle` 追加进去：

```ts

// 实际 cancel 值 = ".react-resizable-handle,.my-no-drag"

dragConfig={{ cancel: ".my-no-drag" }}

```

### 12.13 布局不可变性原则

所有 layout 操作均**返回新数组，不修改原数组**，TypeScript 类型定义为 `readonly LayoutItem[]`。

```ts

// ✅ 正确：始终传入新数组

setLayout([...layout, newItem]);

setLayout(layout.filter(item => item.i !== removeId));

// ❌ 错误：直接 push 修改原数组

layout.push(newItem);

setLayout(layout); // React 同引用不更新！

```

在 `onLayoutChange` 中收到的 layout 已是新数组，可直接存入 state：

```ts

<GridLayout

onLayoutChange={(newLayout) => setLayout(newLayout)} // 安全，直接赋值

/>

```
