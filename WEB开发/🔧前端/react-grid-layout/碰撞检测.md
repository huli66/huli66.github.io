# React Grid Layout — 碰撞检测与布局重排机制（面试文档）

  

> 基于 react-grid-layout v2 源码，深度解析拖拽/缩放时的碰撞检测、级联推挤与压缩重排流程。

  

---

  

## Q1：拖动一个 item 改变位置后，是怎么进行碰撞检测并重新布局的？会遍历所有项吗？

  

### 概述

  

整个过程分为**两个独立阶段**，在每一帧的 `onDrag` 回调中依次触发：

  

```

onDrag

├─ 阶段一：moveElement() — 碰撞解决（推挤其他项）

└─ 阶段二：compact() — 压缩重排（消除空白间隙）

```

  

---

  

### 阶段一：碰撞解决 — `moveElement`

  

**入口**（`GridLayout.tsx`）：

  

```ts

// 每帧拖拽时执行

const newLayout = moveElement(

currentLayout,

l, // 被拖动的项

x, y, // 新坐标（网格单位）

true, // isUserAction

preventCollision,

compactType,

cols,

allowOverlap

);

setLayout(compactor.compact(newLayout, cols));

```

  

**`moveElement` 内部流程**：

  

```ts

// 1. 先原地修改被拖项的坐标（直接 mutate）

l.x = x;

l.y = y;

l.moved = true;

  

// 2. 对全部 n 个项执行碰撞检测（O(n)）

const collisions = getAllCollisions(sorted, l);

  

// 3. 对每个碰撞项，调用 moveElementAwayFromCollision 推开它

for (const collision of collisions) {

if (collision.moved) continue; // 已移动过的跳过，防止循环

moveElementAwayFromCollision(layout, l, collision, ...);

}

```

  

**碰撞判断本身是 O(1) 的 AABB 包围盒检测**（4 次整数比较）：

  

```ts

function collides(l1, l2): boolean {

if (l1.i === l2.i) return false; // 自身不碰自身

if (l1.x + l1.w <= l2.x) return false; // l1 完全在 l2 左侧

if (l1.x >= l2.x + l2.w) return false; // l1 完全在 l2 右侧

if (l1.y + l1.h <= l2.y) return false; // l1 完全在 l2 上方

if (l1.y >= l2.y + l2.h) return false; // l1 完全在 l2 下方

return true;

}

```

  

**结论：是的，会遍历全部 n 个元素**，但每次判断极廉价（4 次整数比较），100 个元素只有约 400 次操作。

  

---

  

### 阶段二：压缩重排 — `compact`

  

`moveElement` 结束后立即对全部元素按压缩策略重排（默认垂直压缩）：

  

```ts

// 按"从上到下、从左到右"排序后逐项处理

const sorted = sortLayoutItemsByRowCol(layout);

for (const item of sorted) {

// 尽量往上移，贴住上方最近的元素

while (item.y > 0 && !getFirstCollision(compareWith, item)) {

item.y--;

}

compareWith.push(item); // 位置确定后加入基准集，供后续项参考

}

```

  

**关键优化：排序后提前退出**

  

```ts

// resolveCompactionCollision 内部

for (let i = itemIndex + 1; i < layout.length; i++) {

// 无静态项时：一旦后续项的 y 坐标超过当前项底部，停止扫描

// （排序保证后面的项只会更靠下，不可能再与当前项碰撞）

if (!layoutHasStatics && otherItem.y > item.y + item.h) break;

if (collides(item, otherItem)) {

resolveCompactionCollision(layout, otherItem, ...); // 递归推挤

}

}

```

  

---

  

### 复杂度汇总

  

| 阶段 | 操作 | 时间复杂度 |

|---|---|---|

| `collides()` 单次判断 | 4 次整数比较 | O(1) |

| `getAllCollisions()` | 遍历全部 n 项 | O(n) |

| `moveElement()` 主体 | getAllCollisions + 递归推挤 k 个碰撞项 | O(n + k·n) |

| `compact()` | n 项各自上移 + 提前退出优化 | 最坏 O(n²)，通常远小于此 |

| **每帧（onDrag）合计** | moveElement + compact | 最坏 O(n²) |

  

---

  

### 为什么实际上不卡

  

1. **单次碰撞判断是纯整数运算**，即使 n=200 也只有 ~800 次操作

2. **排序后提前退出**：无静态项时，超过当前行范围的元素直接 break，实际扫描量远小于 n

3. **`moved` 标记防重入**：已被推挤过的项直接跳过，杜绝重复处理

4. **拖拽期间不通知外部**：`onLayoutChange` 只在 `onDragStop` / `onResizeStop` 时触发，拖拽过程只更新内部 state，不引起外部重渲染

## Q2：碰撞项被移开后，它后面的项如何跟着被推动？（级联推挤）

  

### 核心机制：`moveElement` 与 `moveElementAwayFromCollision` 相互递归

  

不是通过循环遍历"后面的项"，而是通过**深度优先递归**自然传播：

  

```

moveElement(A 移动到新位置)

└─ 检测到 B 与 A 碰撞

└─ moveElementAwayFromCollision(推开 B)

└─ moveElement(B 移动到新位置) ← 递归

└─ 检测到 C 与 B 碰撞

└─ moveElementAwayFromCollision(推开 C)

└─ moveElement(C 移动到新位置) ← 继续递归

└─ 检测到 D 与 C 碰撞

└─ ...（直到链尾无碰撞为止）

```

  

**`moveElementAwayFromCollision` 的末尾**就是再次调用 `moveElement`，把推挤动作传递下去：

  

```ts

function moveElementAwayFromCollision(layout, collidesWith, itemToMove, ...) {

// 先尝试向上/向左移动（只在用户直接操作时尝试一次）

if (isUserAction) {

// 检查上方是否有空间 ...

if (!firstCollision) {

return moveElement(layout, itemToMove, fakeItem.x, fakeItem.y, ...); // 往上移

}

}

  

// 默认：向下/向右移动 1 格，然后继续传播

const newY = compactV ? itemToMove.y + 1 : undefined;

return moveElement(layout, itemToMove, undefined, newY, ...); // ← 递归入口

}

```

  

---

  

### 关键实现细节：坐标是原地修改（mutate）的

  

`moveElement` 直接修改 `LayoutItem` 对象上的 `x`、`y`、`moved` 属性，而不是返回新对象：

  

```ts

// 直接修改，所有递归层共享同一份对象

(l as Mutable<LayoutItem>).x = x;

(l as Mutable<LayoutItem>).y = y;

(l as Mutable<LayoutItem>).moved = true;

```

  

因此，当 B 被推到新坐标后，下一层递归调用 `getAllCollisions` 时用的就是 B 的**最新坐标**，不会在旧位置上重复检测。

  

---

  

### 防止死循环：`moved` 标记

  

假设 A 推 B，B 推 C，C 在新位置上又碰到了 B：

  

```ts

for (const collision of collisions) {

// B 已设置 moved=true，直接跳过，不会被反向推回

if (collision.moved) continue;

moveElementAwayFromCollision(layout, l, collision, ...);

}

```

  

`moved` 标记保证每个项在同一次拖拽操作中最多被推挤一次，从根本上杜绝循环递归。它在每次 compact 结束时统一重置：

  

```ts

// compactor.compact() 末尾

l.moved = false;

```

  

---

  

### 一次完整的链式推挤示意（垂直压缩）

  

```

初始状态（4 个项纵向排列）：

A y=0, h=1

B y=1, h=1

C y=2, h=1

D y=3, h=1

  

操作：把 A 拖到 y=1

  

执行 moveElement(A → y=1):

A.y=1, A.moved=true

getAllCollisions(A) → [B]

→ moveElementAwayFromCollision(推开 B):

B 下方无空间，执行 moveElement(B → y=2):

B.y=2, B.moved=true

getAllCollisions(B) → [C]

→ moveElementAwayFromCollision(推开 C):

执行 moveElement(C → y=3):

C.y=3, C.moved=true

getAllCollisions(C) → [D]

→ moveElementAwayFromCollision(推开 D):

执行 moveElement(D → y=4):

D.y=4, D.moved=true

getAllCollisions(D) → [] ← 无碰撞，递归结束

  

最终位置：A=1, B=2, C=3, D=4

  

执行 compact() → 所有项尽量上移，moved 全部重置为 false

最终稳定位置：A=0, B=1, C=2, D=3（compact 把 A 压回顶部）

```

  

---

  

### 三种特殊模式对比

  

| 模式 | 碰撞时的行为 | 有无级联推挤 |

|---|---|---|

| 默认（normal） | 递归推开碰撞项，形成级联 | ✅ 有 |

| `preventCollision: true` | 被拖项弹回原位，不推任何人 | ❌ 无 |

| `allowOverlap: true` | 直接克隆布局返回，允许重叠 | ❌ 无 |

| 碰到 `static` 项 | 推开**被拖项**（而非静态项） | ✅ 有（方向反转） |

  

```ts

// preventCollision：检测到碰撞直接还原

if (hasCollisions && preventCollision) {

l.x = oldX;

l.y = oldY; // 弹回原位，不推任何人

l.moved = false;

return layout;

}

  

// allowOverlap：不检测碰撞，直接返回

if (hasCollisions && allowOverlap) {

return cloneLayout(layout); // 允许重叠落下

}

  

// 碰到静态项：推被拖的项，而不是静态项

if (collision.static) {

moveElementAwayFromCollision(layout, collision, 被拖项, ...);

// ↑ 注意参数顺序反转：被推的是 l（被拖项），而不是 collision（静态项）

}

```

## 总结：完整调用链（一次拖拽的全过程）

  

```

用户鼠标移动

↓

GridItem.onDrag (每帧触发)

↓ 计算网格坐标、应用 constraints

GridLayout.onDrag (i, x, y, data)

↓

moveElement(layout, 被拖项, x, y) ← 阶段一：碰撞解决

├─ 更新被拖项坐标（原地 mutate）

├─ getAllCollisions() → O(n) 遍历

└─ 对每个碰撞项 → moveElementAwayFromCollision()

└─ moveElement(碰撞项, 新坐标) ← 递归，直到链尾无碰撞

↓

compactor.compact(newLayout, cols) ← 阶段二：压缩重排

├─ 按行列排序全部项

├─ 每项尽量向上移动（贴住上方最近项）

└─ moved 标记全部重置为 false

↓

setLayout(finalLayout) ← 触发 React 重渲染

↓

（松手时）onDragStop

└─ onLayoutChange(finalLayout) ← 通知外部，外部 setState

```
